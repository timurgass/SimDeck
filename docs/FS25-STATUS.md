# Farming Simulator 25: состояние интеграции

В версии 0.8.4 доступен пульт из 54 действий на пяти страницах. Companion выбирает процесс `FarmingSimulator2025Game`, отправляет нажатия в активное окно игры и умеет прочитать собственный `inputBinding.xml` игрока. Чтение не меняет файл игры. Пользовательские кнопки SimDeck сохраняются; перед импортом создаётся копия `settings.json`.

`fs25-mockup.html` — самостоятельный **макет** девяти фермерских экранов с фиксированным примером данных. Он не подключён к Companion, не читает сейв и не показывает живую телеметрию. [План сезона](FS25-SEASON-PLAN.md) описывает будущий формат, загрузчик и движок правил пока не реализованы.

## Следующие части модуля

1. Разбор установленной игры в `SimDeck.Core`: культуры, месяцы посева, расход семян, урожайность, цены и совместимость техники. Нужны фикстуры из игры и тесты для версии данных. Нельзя подставлять придуманные числа.
2. Чтение сейва в отдельном адаптере приложения. Сейв меняется только при сохранении; данные должны иметь время последнего обновления и становиться устаревшими, а не выдаваться за поток в реальном времени. Следить за изменением файла с повтором после временной блокировки записи.
3. Отдельный мод игры для недоступных в сейве значений, если он действительно потребуется: площади полей, текущие цены станций и склад. Версию схемы данных согласовать до реализации.
4. Правила фермы и загрузка плана сезона с валидацией. Ошибка нового JSON не должна стирать прежний план.
5. Экраны по макету в Safari и Android. Показывать источник и свежесть чисел; макетные числа не переносить как реальные показания.
6. Кнопки погрузчика с долгим удержанием — после проверки поведения `hold` в живой игре. Отключение ввода или потеря фокуса должны отпускать клавиши.

## Архитектурные решения

- `Fs25Details` можно добавить как отдельное поле телеметрии по существующему образцу F1/ACC, не меняя формат других игр. Источник FS25 лучше оформить отдельным классом с `Start/Stop` и публикацией в `TelemetryHub`, без переустройства работающих UDP и Shared Memory адаптеров.
- Кнопки игры регистрируются через `GameProfiles.KnownIds`, `AdditionalProfiles.All()` и повышение `CatalogVersion`. Установленные пользовательские профили нельзя перезаписывать при миграции.
- Справочные и пользовательские файлы хранить в `%LOCALAPPDATA%/SimDeck/` в разных папках. Папку установленной игры читать только для справочника, не изменять. Путь к документам получать через `Environment.SpecialFolder.MyDocuments`, поскольку он бывает перенаправлен.
- Парсер клавиш FS25 — частный адаптер игры. Обобщать его на другие игры только при появлении второго реального формата и тестов.
- Пульт Android и Safari должны использовать одинаковые `DeckAction` и протокол. Игра может иметь особые экраны, но базовые действия работают в обоих клиентах.
- Для `InputEngine` удержание поддерживается продлеваемой арендой; длинные действия сначала проверяются вручную, особенно после сворачивания игры или потери соединения.

Порядок работы и критерии передачи нового модуля: [DEVELOPING-GAMES.md](DEVELOPING-GAMES.md). Ручная проверка FS25: [FS25-TESTING.md](FS25-TESTING.md).
