# Добавление игры и передача работы в SimDeck

Этот файл предназначен внешнему разработчику. Работайте в отдельной ветке от актуального `main`, открывайте PR или передавайте Git bundle/патчи. Исходники, макет и готовая функция должны называться по-разному: макет не считается работающим экраном.

## Профиль кнопок

1. Добавьте стабильный ID игры в `GameProfiles.KnownIds` и фабрику профиля в `AdditionalProfiles.All()`. Повысьте `CatalogVersion`. Новая версия каталога должна добавить отсутствующий профиль один раз и сохранить редактирование существующих профилей.
2. Укажите имя процесса Windows **без `.exe`**. Действия — `DeckAction(id, page, label, description, key, gesture, group)`; до 96 кнопок. `id` постоянен при обновлениях, страницы и подписи пригодны для телефона. Ключи должны проходить `WindowsInput.ParseBinding`.
3. Для собственных раскладок игры сделайте отдельный импортёр. Он читает игру только для чтения, не меняет настройки игрока, оставляет пользовательские действия SimDeck и создаёт резервную копию перед записью. FS25 — пример такого импортёра.
4. Если действие выполняется по удержанию, проверьте отпускание при потере фокуса и соединения. `press`, `hold` и особый BeamNG `tapThenHold` нельзя менять без проверки обоих клиентов.

## Телеметрия и экраны

Сначала зафиксируйте **официальный источник данных, версию формата, единицы измерения и частоту обновления**. Разбирайте данные в `SimDeck.Core`, чтение сокета/Shared Memory/файла держите в отдельном адаптере `SimDeck.App`. Публикуйте через `TelemetryHub` с корректным временем; старый кадр не должен выглядеть живым. Расширение `Telemetry` и протокола сопровождайте совместимыми фикстурами и проверками в Android/Safari. Не рисуйте предполагаемые цифры там, где источник их не даёт.

Для особых экранов добавьте одинаковые данные и действия в Safari и Android. Если делаете сначала макет, пометьте его демонстрационным и приложите список того, что пока не подключено. Не встраивайте реальные пользовательские сохранения в публичные файлы.

FS25 теперь служит примером медленного файлового источника: `Fs25SaveWatcher` повторяет чтение при частичной записи, публикует через `TelemetryHub` и помечает старый сейв. Исходный парсер, план и правила находятся в Core; Android использует `Fs25Data.kt`, Safari — `Browser/fs25.js`. Синтетические XML в `companion/SimDeck.Tests/fixtures/fs25/` допустимы для PR. Файлы установленной игры и настоящие сохранения не прикладывайте. Перед публикацией проверьте размер JSON-снимка и отсутствие рекурсивных вычисляемых свойств.

## Что приложить к PR или ZIP

- База (commit SHA), список изменённых файлов, поддерживаемая версия игры и формат источника.
- Что **работает сейчас**, что существует только как макет, что требует установленной игры/мода.
- Команды сборки и результаты .NET/Android тестов; отдельный список ручных проверок **нажатиями в игре** с версией игры. Не называйте кодовую проверку подтверждением поведения игры.
- Миграция настроек, обратная совместимость, способ отката и пример обезличенной фикстуры.
- Для нового адаптера — описание ошибки/отключения и того, когда данные считаются устаревшими.

Команды из корня: `dotnet run --project companion/SimDeck.Tests/SimDeck.Tests.csproj -c Release`, `dotnet build companion/SimDeck.App/SimDeck.App.csproj -c Release`, затем в `android` — `./gradlew testDebugUnitTest assembleDebug`. Версия .NET задаётся `global.json`; Android требует SDK/JDK по конфигурации Gradle.

## Экран нового профиля

Согласованный макет нужно перенести в оба клиента: Android — `ProfileDashboard.kt`/`ProfileDesign.kt` (F1 отдельно в `F1Dashboard.kt`), Safari — `Browser/dashboard.js`/`dashboard.css`/`profile-design.css`. Используйте существующие `Control` и `actionButton`, чтобы сохранить блокировки ввода, отпускание удержаний и пользовательские назначения. Не создавайте собственный независимый путь отправки команд.

Проверяйте не только цвета: композицию приборов, размеры и подписи, быстрые действия, полный каталог и пользовательские страницы. Обязательны телефон и планшет в двух ориентациях, отсутствующая/устаревшая телеметрия, выключенный ввод, удержание и смена страницы. [Воспроизводимая проверка](../tools/qa/README.md) · [Снимки и результаты 0.9.2](UI-VERIFICATION.md).

Для автоматического выбора техники используйте общий контракт `VehicleInfo`; не назначайте класс по названию кнопки или прошлому нажатию. Метаданные и геометрия обновляются при пересадке, неизвестные возможности остаются nullable. [Контракт и источники](AUTO-VEHICLE.md) · [Проверки 0.9.3](VEHICLE-VERIFICATION.md).
